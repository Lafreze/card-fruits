# 水果叠叠乐 · Fruit Stack

卡牌三消、物理合成与随机天气。56 种卡通水果、53 个关卡、5 种玩法、22 种技能与道具。

## 难度与星级

- 简单：8 格，通关 1 星。
- 普通：7 格，通关 2 星。
- 困难：6 格，通关 3 星。
- 隐藏四星：**该关取得三星后解锁**，5 格、90 秒合成时限。初始特殊牌增多，每 10–14 秒可能出现短时冰锁、荆棘球或乱果雨。失败不授星，重复通关保留最高星级。菜单和后台暂停也暂停计时。

四星仅用于闯关；每日鲜摘固定困难，其他模式使用三档普通难度。旧大师、极限的本机历史记录显示为困难，不会凭旧分数直接授星。

新增蔓越莓、杏子、黑莓、红毛丹、榴莲、刺梨与六个对应关卡，图鉴和合成链同步扩展。保留原来的 50 份独立卡通 WebP，新六果为独立矢量插画，无水果底部投影，资源地址带内容指纹。

清障剪清除荆棘球并解除最多三张冰锁/藤蔓卡；果园风车提供 8 秒向左风。每局各一次，温室可升级，无有效目标不扣次数。新增跳跳冰雹和蜜露，天气共八种。已有弹力垫、天气仪、透视镜、聚果场等继续可用。

手机对局铺满视口，横竖屏切换保留对局；卡片用实际旋转圆角面计算遮挡，阴影不拦截点击。物理使用 120 Hz 固定步进，普通合成必须接触，合成动画期间保留实体。

## 服务器成绩与身份

对局结束自动提交到服务器，公开排行榜每个玩家显示一条当前筛选条件下的最佳成绩。主线按关卡、星数、分数排序。修改昵称会更新所有公开记录，不会生成新玩家。同一公网 IP 共用一个玩家；换 IP 会识别为另一位玩家。这是按 IP 识别的休闲榜，不提供账号身份认证或服务器权威模拟防作弊。

服务器将 IP 用持久密钥进行 HMAC 转换，公开接口不返回原始 IP。昵称、关卡星级、各规则最佳成绩和幂等对局记录保存在 `players.json`；`identity.key` 必须与成绩文件一起持久保存、备份。采用临时文件写入、刷盘、原子替换，损坏存档不会被自动清空。此实现要求**单个服务器进程/副本**，不依赖数据库。

断网时成绩写入浏览器待同步队列，恢复联网、重新打开游戏或每 30 秒重试。重复提交不会产生重复榜单记录。新设备在同一 IP 下可恢复服务器星级与已通关关卡；果币、温室等养成仍保存在本机，可在「我的存档」导出。历史本机成绩只作离线缓存，不自动伪装成服务器认证通关。

## 运行和部署

需要 Node.js 22.18+（推荐 24）。

```sh
npm install
npm run dev
npm test
npm run build
npm start
```

开发前端 5173 代理 `/api` 到 3000；生产 Express 同时提供网页与接口。公开排行榜需要后端，不能只部署 `dist/`。

生产必须挂载持久目录并运行一个副本：`DATA_DIR=/data`（将数据卷挂载到 `/data`）。本机默认 `server/data`，已加入 git 忽略。不要把身份密钥提交进仓库。

Railway 沿用仓库启动配置；请给服务添加持久数据卷。代码自动读取 [`RAILWAY_VOLUME_MOUNT_PATH`](https://docs.railway.com/volumes)，自动使用 Railway 公共 HTTP 入口提供的 [`X-Real-IP`](https://docs.railway.com/networking/public-networking/specs-and-limits)。该自动识别仅适用于 Railway 公共 HTTP 入口，不应将服务通过其他不清洗请求头的入口暴露。未挂载数据卷时重新部署仍可能丢失成绩；代码推送本身不会创建数据卷。

其他主机默认只认连接来源 IP，忽略伪造转发头。若有自己的反向代理，请按真实网络配置 `TRUST_PROXY` 为可信代理 IP/CIDR 或确定的跳数，并禁止绕过代理访问源站。不要将所有来源无条件设为可信。

接口：`GET/PATCH /api/player`、`POST /api/runs`、`POST /api/scores`、`GET /api/leaderboard`、`GET /api/health`。排行榜和身份响应禁用缓存，避免代理共享玩家档案。

## 验证

自动检查覆盖全部关卡的合法牌阵与消牌路线、圆角遮挡、接触合成、素材指纹、星级授予、隐藏难度门槛、计时、天气、本机备份，以及服务器 IP 身份、伪造转发头、昵称修改、跨玩家提交拒绝、重复提交和磁盘重载。浏览器检查覆盖手机横竖屏、真实通关、自动上传和技能效果。
